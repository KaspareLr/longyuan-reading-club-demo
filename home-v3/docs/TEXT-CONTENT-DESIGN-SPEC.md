# 龙源读书会 · 文案长度与超长内容设计约束

版本：1.0 · 2026-11-02  
适用：原版读书会首页及共读、领读人、活动、会员、个人空间、书库、刊库、详情页、目录、阅读器、专题、检索、弹窗与表单。独立探索首页不自动套用。  
用途：供设计、开发、内容编辑与其他 AI 共用。本文是目标规范，不代表现有页面已经实现全部展开行为。

## 1. 给执行 AI 的总指令

1. 必须先确认字段的页面位置和任务，再选择完整显示、预览省略或原位展开。不得把全站文字统一设为两行省略。
2. 分开处理录入上限、预览字数和展示行数。任何视觉截断均不得改写原始数据、破坏 HTML 结构、删除图标或改变链接。
3. 已发布、外部导入或历史内容超过规范时，保留完整数据，使用本规范的展示策略；不得自动删除、改名、缩写、重新生成或拒绝展示。
4. 必须让移动端用户找到全文。原生 title、鼠标悬停提示和无障碍标签只能作为补充，不是全文入口。
5. 详情页的主标题、关键身份、决策信息与阅读正文完整显示；列表的预览可以省略；当前页需要读完但较长的介绍提供原位展开。
6. 按实际溢出显示展开按钮。桌面不溢出、移动端溢出时，只在移动端显示；短文本不显示无效按钮。
7. 不通过缩小字号、压缩行高、固定过小高度或隐藏整个区域解决超长问题。延续现有字体、字重、字号、间距与图片比例。
8. 不能借本规范修改内容主题、交互入口、按钮含义、购买条件或数据逻辑。
9. 优先级：正文与关键信息完整可读 > 全文可达 > 字段专项规则 > 通用卡片规则 > 固定卡片等高。
10. 新增字段必须先补充规则；无法归类时采用完整换行，不能默认截断。

## 2. 长度的三个独立概念

| 名称 | 含义 | 超出后的动作 |
|---|---|---|
| 录入上限 authoringMax | 本项目新创建或主动编辑的字段最大长度 | 保留输入并提示修改，校验失败时阻止提交；不得静默截掉 |
| 预览字数 previewChars | 当前卡片 / 折叠状态最多展示的可见字符数 | 仅截断展示副本，保留完整值，按 P / E / M 提供全文入口 |
| 展示行数 desktopLines / mobileLines | 在当前容器、字号和视口下最多占用的行数 | 与预览字数共同生效，先达到的限制决定收起态；不得把行数换算成固定字数 |

字段表中的“录入上限”不包含自动生成的省略号；“预览字数”包含省略号。例如 40 字预览上限，发生字符截断时最多 39 个原文字符加一个“…”；未超出则显示全部 40 字，不添加省略号。CSS 因实际换行而产生的省略同样按展示限制处理。

新建书名、刊名、文章标题等字段应复用同一份完整值；不同位置只改变预览约束。不得为适应卡片而保存一个被截断的标题。组合显示字段如“作者 · 出版社”中的分隔符计入预览字数，其子字段仍各自保留完整值。

## 3. 统一字数计算

- 人类可见的字符按 Unicode grapheme cluster 计数。中文、英文、数字、标点、空格各计 1 个；一个组合 emoji、带肤色 emoji 或组合字母计 1 个。
- 换行计 1 个字符；仅将 CRLF 统一为 LF。不要静默删除首尾空格、合并段落或执行改变原文的 Unicode 归一化。
- 富文本统计可见文字，不把 HTML 标签、图片、图标、隐藏辅助文字或展开按钮计入正文长度。正文中的链接文字计数，链接 URL 属性不计数。
- 前端、服务端与计数器使用同一算法；浏览器可使用 `Intl.Segmenter`。缺少该接口时需提供符合 grapheme cluster 的替代实现，不能用 `slice()` 或 `Array.from()` 冒充完整支持。
- 邮箱与兑换码按已定义的 ASCII 格式校验，254 / 32 是长度上限，不替代邮箱语法或兑换码有效性校验。
- `maxlength` 使用 UTF-16 单元，不能直接等同于本规范的可见字符计数。实现可见字符校验时应避免它提前阻止合法 emoji 输入。

## 4. 四类展示策略

| 代码 | 策略 | 适用场景 | 溢出时的全文入口 |
|---|---|---|---|
| F | 完整显示 | 主标题、导航操作、关键身份、价格日期地点、阅读正文 | 原位置完整换行；不折叠、不省略 |
| P | 列表预览 | 标题、摘要、卡片简介、目录条目、搜索结果 | 已有详情入口且详情含该字段完整值时，使用该入口；否则转为 E |
| E | 原位展开 | 本页需要阅读的介绍、推荐语、评论、笔记、个人签名 | 原位置“展开全文 / 收起” |
| M | 身份与来源预览 | 卡片内作者、职务、出版社、来源等元信息 | 详情中能看到完全相同字段才允许省略；否则增加原位“查看完整信息 / 收起” |

### 4.1 省略 P 的必要条件

必须同时满足：这是列表或导航预览；有清晰可点击的详情入口；详情能够查看被省略的同一字段全文。只存在一个“阅读全文”按钮还不够：如果详情里没有卡片摘要，就不能据此声称摘要全文可达。

卡片已有详情入口时，不额外增加“展开标题”或“展开摘要”。若缺少有效详情，则 P 必须转为 E，并把展开按钮与卡片跳转分离；不允许把 button 嵌在 a 中，也不允许点击展开时触发整卡跳转。

### 4.2 必须展开 E 的情况

- 首页的读书会介绍、独立领读语等，没有承载同一字段全文的详情页。
- 详情中的图书简介、期刊介绍、领读人介绍、编辑推荐与活动详细导语。
- 独立评论、笔记、阅读观点与个人签名，所在位置需要用户读完整段内容。
- 摘要没有详情入口，或者详情中不能读到原摘要全文。

E 的收起态受表内字数与行数限制；展开态显示完整值，不再应用任何字符截断、行截断或固定高度。每条内容独立展开；不得用“展开更多”一次展开整个列表。

### 4.3 必须完整显示 F 的情况

- 页面主标题、详情书名 / 刊名 / 文章名 / 活动名，以及详情中的作者与领读人姓名。
- 价格、币种、计费周期、有效期、日期、时间、地点、报名条件、限制说明、权益条款、FAQ、校验错误。
- 阅读正文、AI 回答、阅读任务的必读指令、需要执行的步骤。
- 按钮名称、操作导航、关键状态与进度。文案过长时调整布局或明确改写编辑文案，禁止隐藏动作含义。

导航允许调整间距或分行；弹窗标题允许增加高度；长书名允许标题区增高。禁止让这些内容覆盖图片、操作或正文。表中对 F 给出的录入上限是新文案约束；历史或外部数据超长仍完整显示。

### 4.4 标题与简介的上下文覆盖

相同字段在不同位置可以使用不同策略。例如书名在书库卡片为 P，两行省略；进入详情后为 F，全量换行。表中的“页面主标题”和“详情标题”规则必须覆盖卡片标题规则，不得仅凭 h1 / h2 / h3 标签全局截断。

## 5. 逐字段限制

### 5.3 字段表的专项例外（优先于表格）

1. 详情中的作者、出版社、来源、领读人姓名与职务：使用 F。表中的 M 只用于紧凑的列表、卡片与阅读器侧栏。
2. “个人昵称”的录入统一为 12 字；不同位置不得出现 12 字、20 字、24 字的录入标准并存。详情完整显示；导航空间不足时优先移动账户入口，不把昵称当成可以丢失的信息。
3. “领读人简介预览”与“图书简介”的较大上限用于新编辑内容。外部简介即使超出也保留全部，E 展开后展示完整原文。
4. 会员权益说明如果包含价格、收费周期、资格、使用次数或限制条款，必须整体升级为 F，不能把限制部分放在省略号之后。
5. 阅读任务说明若包含必须执行的步骤、截止时间或提交要求，升级为 F；只有非必要的补充说明可使用 E。
6. 评论与笔记不受“摘要 120 字”规则约束。列表预览默认使用 E，收起态最多 200 字、4 / 4 行；输入上限分别为 1000 / 2000 字。若已有真实的同条详情页可使用 P。
7. 阅读观点预览 300 字、6 / 6 行；有同条观点详情可使用 P，否则使用 E。出处按 M，不删除来源。
8. 筛选项与导航在本项目中是编辑控制的短文案。超长历史标签完整换行，不应给每个标签添加展开按钮。
9. 状态、日期、参与人数和进度采用结构化数据及格式化显示，不通过截取字符串缩短数字。需要紧凑数字格式时，应另行定义单位与精度规则。
10. 空字段不生成省略号或展开按钮；可选字段缺失时收起该字段间距，必要字段缺失时沿用页面已有空态。

已有超长资料打开时不得自动改写；编辑表单显示实际字数和错误，用户完成修改后才可保存。前端和服务端均须校验；前端原型没有服务端时，交付说明必须明确这一点。

## 6. 何时出现展开按钮

采用下列判定顺序，禁止仅凭字符串长度判断：

1. 先读字段策略。F 永远不出现展开按钮；P / M 先验证同字段全文入口是否存在，不存在则转 E。
2. 对 E 使用完整数据计算：是否超过 previewChars，或者按收起态宽度和字体渲染后超过允许行数。任一成立即为溢出。
3. 使用完整值的隐藏测量副本或不修改原文的测量方式。不要先把 DOM 截短，再通过已截短内容判断“没有溢出”。
4. 溢出时显示按钮，不溢出时隐藏按钮并完整显示原文。需要考虑实际宽度、字体加载、字号、语言、内容更新与容器变化。
5. 容器 resize、断点切换、字体加载完成、筛选、路由变化、弹窗打开与异步内容更新后重新测量。可使用 ResizeObserver；不能依赖写死的像素高度。
6. 展开后的 resize 不应擅自把用户已展开的内容收起。仅当内容实体替换或用户主动收起时重置。切换筛选后保留还是重置须以稳定内容 ID 管理，同页同条内容不得随机变化。

## 7. 展开与收起的交互规范

| 项目 | 必须遵守的行为 |
|---|---|
| 按钮文案 | 介绍 / 评论 / 笔记使用“展开全文 / 收起”；元信息使用“查看完整信息 / 收起” |
| 位置 | 紧随被截断的文字，独立占位；不得覆盖尾行、图片或卡片跳转区 |
| 控件 | 使用 button type="button"；不能使用无语义 span，不能作为表单提交按钮 |
| 无障碍 | aria-expanded 与真实状态一致，aria-controls 指向该段内容的唯一 ID；可访问名称说明展开哪条内容 |
| 键盘 | Tab 可聚焦，Enter / Space 可切换，焦点留在触发按钮；不能展开后把焦点跳到页首 |
| 展开态 | 移除字符预算、line-clamp 和固定高度，显示原始完整内容与段落、链接 |
| 收起态 | 恢复同一套字数和行数预算；按钮回到段落尾部，仍可访问 |
| 滚动 | 默认不滚动；收起导致按钮离开视口时，才以最小必要位移保持触发位置可见，不无条件 scrollIntoView |
| 动画 | 可不动画；如使用高度 / 位移动画，须可中断并尊重 prefers-reduced-motion，禁止动画期间遮挡操作 |
| 状态范围 | 每条内容独立；使用稳定实体 ID 和字段名区分，不使用数组索引共享展开状态 |

原文中的链接必须正常可访问。不得把“点击全文区域任意位置”作为唯一展开方式。若折叠实现会让不可见链接仍进入 Tab 顺序，必须调整实现，使收起态只暴露可见交互，展开后恢复全部链接。

## 8. 样式与技术实现约束

- 单行 P / M 使用 ellipsis；多行 P / E / M 可使用 line-clamp，并提供必要的兼容处理。不要把 `height: 3em` 当成“三行”。
- Flex / Grid 的文字子项按需设置 min-width: 0；图片和必要操作不能被长文挤出容器。移动端可换行调整布局，不一律维持固定高度。
- 中英文混排优先保持自然断行；长 URL、连续英文、邮箱可使用 overflow-wrap: anywhere。不要对全站使用 word-break: break-all。
- 不通过 font-size、transform: scale 或 letter-spacing 的临时压缩来容纳更多字。
- 保留换行与富文本结构；展示副本需要截字时，不能用 textContent 替换整个有图标、链接、强调或控件的容器。
- title 提示可保留完整值，但不作为触屏和键盘的唯一全文途径。无障碍名称与可见内容不要互相矛盾或重复播报整段原文。
- 前端字段数据与 UI 状态分离。完整原文用于详情、复制、分享、搜索与编辑；省略号只属于展示层，不能写回数据、localStorage 或接口。
- 字段规则通过明确的页面 / 组件 / 字段绑定，避免仅按通用标签 h1、p、span 扫描。不得误伤价格、计时器、图表标签、阅读正文或表单控件。
- 首页每日一读及精选文章的 2:3 图片比例保持不变；文字展开只能增加文字区域高度，不能拉伸图片或截掉展开后的正文。

## 9. 示例：同一段内容在不同位置

| 内容与位置 | 收起态 | 超长后 |
|---|---|---|
| 文章卡片标题 | 48 字、2 行 | P；进入文章页查看标题全文 |
| 文章详情主标题 | 完整换行 | F；即使超过 80 字的历史标题也保留显示 |
| 首页文章摘要 | 120 字、3 行 | 同摘要在详情存在则 P；详情没有该摘要则 E |
| 图书详情简介 | 800 字、6 行 | E；展开后展示全部原文，外部简介超出 800 字也不丢失 |
| 领读人介绍 | 500 字、8 行 | E；本页展开，不强迫跳转 |
| 评论列表中的评论 | 200 字、4 行 | E；每条独立展开，最多输入 1000 字 |
| 报名截止时间与活动地点 | 完整换行 | F；不允许把门牌、时区或截止时刻省略 |
| 导航里的昵称 | 新录入最多 12 字 | F；调整账户入口宽度或布局，不用悬停替代真实可见信息 |

## 10. 验收要求

每类字段至少覆盖：空值、一个字、上限减一、正好上限、超出一字、超出两倍；另测中文、长英文、连续数字、URL、emoji、换行与富文本链接。

1. 在 320、390、768、1440px 下验证；浏览器 200% 缩放时不丢失内容或操作。允许页面纵向增长，不允许无意的整页横向溢出。
2. P 必须能进入详情读取同一字段全文；详情不得展示仍带省略号的副本。没有同字段全文入口时必须转 E。
3. E 必须在实际溢出时出现按钮。短文本不出现；展开后可读完整值；收起后位置稳定；触屏与键盘都能操作。
4. F 必须完整显示，价格、币种、期限、地点、标题、错误提示和正文不能被截断、折叠或隐藏。
5. 输入法、粘贴、emoji 计数一致。计数器、前端与服务端校验上限相同，不静默丢字。
6. 切换筛选、分页、路由、弹窗、字体加载与容器尺寸变化后规则仍有效；不会叠加按钮、监听器或字数提示。
7. 复制、分享、重新编辑与持久化得到完整原文；不得出现把“…”保存回数据的情况。
8. 最长数据预览必须来自独立测试数据，不覆盖真实内容或用户资料。另用超上限数据验证回退，而不只测试“正好上限”。
